NTuple Production

In the previous post we introduced the physics motivation behind the B⁺ → J/ψ φ K⁺ analysis and set up our CMSSW environment. Now it’s time to actually extract candidates from the raw AOD files and write them into a flat ROOT TTree — the NTuple that all downstream steps (mass fitting, BDT training, systematic studies) will consume.

Why a Custom EDAnalyzer?

CMS Open Data from the 2011 run is distributed as AOD (Analysis Object Data). Unlike the more modern MiniAOD/NanoAOD formats, AOD does not ship pre-built PAT candidates, so there is no plug-and-play B-physics tool available. We need to write our own EDAnalyzer that:

  1. reads reco::Muon and reco::Track collections directly,
  2. applies pre-selection cuts to reduce combinatorial background early,
  3. runs vertex fits on the surviving combinations, and
  4. writes all kinematic and topological quantities into a TTree.

The overall package is called BJpsiPhiK2011 and lives inside the standard CMSSW plugin framework.

The Decay Chain

The full decay we reconstruct is

Five final-state tracks in total: two muons from J/ψ, two kaons from φ, and one bachelor kaon. This means the main combinatorial background grows as O(N²_μ × N³_K), which motivates aggressive but physics-safe pre-selection at every stage.

Two additional trigger-era cuts matter for the 2011 dataset, which is described further below.

Dataset Split: Run2011A vs Run2011B

The 2011 MuOnia dataset is divided into two physics eras that used different displaced dimuon trigger thresholds:

  • Dataset A (Run2011A, run ≤ 173692): triggers fire on J/ψ with pT(J/ψ) > 7 GeV.
  • Dataset B (Run2011B, run ≥ 175833): tighter triggers also require pT(μ₁) > 4 GeV and pT(μ₂) > 4 GeV on top of the J/ψ pT cut.

The different thresholds affect the B mass resolution (harder muons → better tracking resolution), so the two eras are kept separate and can be treated independently in the fit. The code detects the era by run number and applies the extra muon pT cut for Dataset B:

Code Walk-Through

Step 1 — Muon Selection

We loop over the full reco::Muon collection, write kinematic branches for every reconstructed muon (this is what nMu and the muPx/muPy/muPz/... branches record), and then apply quality cuts to build a goodMuons vector used in the J/ψ loop:

Note that muon branches are filled before the cuts, so every reconstructed muon is in the NTuple regardless of whether it ends up in a B candidate. This is useful for isolation studies later.

Step 2 — J/ψ Reconstruction

All pairs of oppositely-charged good muons within the 2.7–3.4 GeV mass window are vertex-fitted with KalmanVertexFitter. Two topological cuts are then applied on the fitted vertex:

Vertex probability > 10% — ensures the two muon tracks are genuinely consistent with a common displaced vertex.

Lxy/σ(Lxy) ≥ 3 — the significance of the transverse displacement from the primary vertex. This is critical: the J/ψ from B decay is displaced, while prompt J/ψ background is not.

Before the vertex fit, the J/ψ mass constraint is computed analytically. This rescales both muon momenta so that their invariant mass equals exactly the PDG J/ψ mass. The constrained momenta (cpx1/cpy1/cpz1, cpx2/cpy2/cpz2) are then used for the 5-body B mass calculation, giving a sharper B mass peak compared to using the raw muon momenta.

Step 3 — Kaon Track Selection

We loop over generalTracks and keep those passing the hit-quality requirements. One important step: muon tracks must be explicitly excluded, or the same track can appear as both a muon and a kaon candidate. The code first tries to match by innerTrack() reference key, then falls back to a ΔR < 0.01 geometric match:

This double-check matters because in AOD the muon’s innerTrack() and the corresponding entry in generalTracks are the same physical object, but the reference keys can occasionally be inconsistent near collection boundaries.

Step 4 — φ Reconstruction

All pairs of oppositely-charged kaon tracks are combined and kept if m(K⁺K⁻) falls in 1.008–1.035 GeV. This window is tighter than the standard ±10 MeV around the PDG φ mass but was chosen to retain ~90% of the φ signal while cutting significantly into the K⁺K⁻ combinatorial background beneath it.

The looser pre-selection window (up to 1.06 GeV) used in the earlier ntuple stage is tightened here to the final analysis window.

Step 5 — B Candidate Assembly

For each (J/ψ, bachelor K⁺) pair, we search the φ candidate list for the best φ. If multiple φ candidates exist for the same event (because more than two kaon tracks pass the selection), the one with the smaller m(K⁺K⁻) — the m(K⁺K⁻)_min candidate — is selected and the rest discarded. This convention directly follows the original analysis strategy: using the larger-mass φ candidate preferentially picks up combinatorial background.

After selecting the φ, a 5-track Kalman vertex fit is performed on all five final-state tracks together (2 muons + 3 kaons). Using all five tracks for the vertex fit — rather than just the 3 kaons — is important: the muon tracks carry strong displacement information and make the vertex probability a much more discriminating variable.

A Note on Kaon Mass Assignment

In the original analysis, kaon tracks are refit with the kaon mass (493.677 MeV/c²) assigned to correct for ionization energy loss in the tracker material. This refit improves the B mass resolution by roughly 1–2 MeV and slightly shifts the peak position.

Performing a full track refit from AOD requires an additional TrackRefitter module in the CMSSW config (with Mass = 0.493677 in the RungeKuttaTrackerPropagator settings), which is non-trivial to set up correctly in CMSSW 5.3.X on 2011 Open Data. In this tutorial version we use the raw generalTracks momenta directly. The resulting B mass peak is slightly broader and shifted compared to the published result, but the effect is small enough not to affect the topological selection or the J/ψφ spectrum search. If you want to match the original resolution precisely, adding the kaon refit is the most impactful single improvement you can make.
